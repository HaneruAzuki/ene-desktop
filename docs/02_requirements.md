## 1. 全体要件

### 1.1 プロダクト定義
- **名称**:Project_ENE(キャラクター:魚川トリミ)
- **対象プラットフォーム**:Windows 10 / 11(Windows 専用)
- **配布形態**:インストール不要の**完全ポータブル**。アプリフォルダ内の `data/` に全状態を保持し、
  Electron の userData も `data/app/` へ向け直す。`%APPDATA%` 等に痕跡を残さず、
  **フォルダ削除＝完全アンインストール**が成立する(NFR-PRIV / NFR-PORT)。

### 1.2 v1.0 のスコープ

v1.0 が提供するもの(ロードマップ・段階の全体像は `01_vision.md` §6 を正本とする):

- 透過表示(PNG / VRM)と、テキスト・音声による会話(Claude)
- 人格・知識プロファイルと Knowledge Router(役の境界=役の外は「知らない」)
- 3層記憶(短期・中期・長期)＋想起エンジン(語彙＋entity＋ベクトルの RRF 合流)・非破壊更新
- 一人の固定キャラ(魚川トリミ)・人生記憶 canon・心(感情価バイアス想起)
- 双方向ローカル音声(STT / TTS / VAD・barge-in・相槌)
- アニメ基盤(状態機械 idle/thinking/talking ＋ emotion 表情差分・口パク)

### 1.3 持たないもの(方針として不採用)

| 不採用 | 理由 |
|---|---|
| **PC 操作機能**(アプリ/ブラウザ/フォルダを開く等) | トリミは PC を操作する手段を持たない。頼まれても chat で「できない」と口調で断る(才能はあるが実行は引き受けない) |
| **会話の逐語ログ** | 全会話の保存はしない。過去を辿る用途は中期記憶の要約が果たす(人間らしい忘却) |
| **複数キャラ切替 UI・キャラ配布** | 一人の固定キャラ(魚川トリミ)である |
| **保存される数値感情/好感度スカラー** | 心は記憶からの導出のみ。数値状態を貯めない |
| **専用モデル(LoRA 等)・テレメトリ/統計収集/クラッシュレポート** | 軽量・ローカルファースト |

## 2. 機能要件(`F-*`)

> 各 `F-*` は時制を持たない**約束**である(現在の v1.0 が満たすべき状態のみを書く)。

### 2.1 キャラクター表示

| ID | 要件 |
|----|------|
| F-DISP-01 | 透過ウィンドウにキャラクター(PNG / VRM)を表示する |
| F-DISP-02 | ウィンドウは常に最前面に固定される |
| F-DISP-03 | キャラクターをドラッグして移動可能 |
| F-DISP-04 | ウィンドウ位置は終了時に保存され、次回起動時に復元される |
| F-DISP-05 | 初回起動時は画面右下にデフォルト配置される |
| F-DISP-06 | 視覚レンダラは `CharacterState` インターフェースで差し替え可能(PNG / VRM) |
| F-DISP-07 | キャラクター上で右クリックするとコンテキストメニューを表示する(話す / 位置リセット / APIキー設定 / クレジット / 終了) |

#### アニメ基盤(F-ANIM)

| ID | 要件 |
|----|------|
| F-ANIM-01 | キャラ表示は状態機械(activity: idle/thinking/talking, emotion, pose)で駆動する |
| F-ANIM-02 | スプライト・状態→画像の対応・フレーム間隔は `{id}/animation.json` で定義(コードにハードコードしない) |
| F-ANIM-03 | idle 中は呼吸の微動(CSS)を再生し、長時間 idle で稀に寝そべり(sofa)へ遷移する |
| F-ANIM-04 | 応答待ち(thinking)中は「考える」表示を出す(待ちの不安を和らげるもので、遅延を隠す演出にはしない。応答自体は常に最小化する・哲学 §1.4) |
| F-ANIM-05 | 応答表示(talking)中は口パクを再生する(メッセージ長に比例した時間ベース) |
| F-ANIM-06 | 応答に emotion 離散ラベルを含め対応表情へ切替。欠落・許可外は `neutral` にフォールバック |
| F-ANIM-07 | emotion は1ターン揮発ラベル。好感度・不機嫌度などの数値状態は持たない |
| F-ANIM-08 | クリックスルー判定(`isOpaqueAt`)は現在表示中フレームの alpha で行う(VRM は 1px readPixels) |
| F-ANIM-09 | クリック音等の UI 音は Web Audio で合成する(外部音源を同梱しない) |
| F-ANIM-10 | アニメ定義が無い・不正な場合は単一 portrait 表示にフォールバックする(後方互換) |
| F-ANIM-11 | フレーム間隔・呼吸/口パク間隔等の数値は定数として一元管理する |

### 2.2 テキスト入力・出力

| ID | 要件 |
|----|------|
| F-IO-01 | キャラクター付近にテキスト入力欄を設置する |
| F-IO-02 | デフォルトでは入力欄は非表示(キャラのみ表示) |
| F-IO-03 | キャラの短いクリック(動かさず素早く離す)で入力欄を展開する |
| F-IO-04 | ESC キーで入力欄を閉じる |
| F-IO-05 | ユーザ入力テキストは Claude API に送信される |
| F-IO-06 | 応答はキャラクター付近に吹き出しとして表示される |
| F-IO-07 | 入力テキストは UTF-8 文字列として扱う |

#### 吹き出しのライフサイクル(F-BUBBLE)

| ID | 要件 |
|----|------|
| F-BUBBLE-01 | 吹き出しは ENE の応答時に表示される |
| F-BUBBLE-02 | 吹き出しは横幅固定(キャラ幅相当、約240px)で縦方向に自動拡張する |
| F-BUBBLE-03 | 最大高さは 400px とし、超過時は内部スクロールを許可する |
| F-BUBBLE-04 | 表示から 30 秒経過で自動消滅する |
| F-BUBBLE-05 | ユーザが新しい入力を送信した時点で、古い吹き出しは即座に消える |
| F-BUBBLE-06 | 吹き出しをクリック、または ESC キーで即座に閉じる |
| F-BUBBLE-07 | 数値(30秒・400px等)は定数として一元管理する |

### 2.3 透過ウィンドウ・操作・終了

#### 透明領域のクリックスルー(F-WIN)

| ID | 要件 |
|----|------|
| F-WIN-01 | キャラの不透明ピクセル上ではマウスイベントを受け取る(キャラと対話可能) |
| F-WIN-02 | キャラ周りの透明領域では、マウスイベントを下のデスクトップに通す(クリックスルー) |
| F-WIN-03 | 透明領域上のクリック・右クリックは、デスクトップアイコン等の操作として処理される |
| F-WIN-04 | この挙動は `setIgnoreMouseEvents(true, { forward: true })` で実装する |

#### マウス操作の判別(F-MOUSE)

| ID | 要件 |
|----|------|
| F-MOUSE-01 | mousedown→mousemove の移動距離 5px 以上 → ドラッグ判定、ウィンドウ移動を開始 |
| F-MOUSE-02 | 移動 5px 未満・押下 500ms 未満で mouseup → クリック判定、入力欄を展開 |
| F-MOUSE-03 | 移動 5px 未満・押下 500ms 以上で mouseup → 長押し扱いで何もしない(誤操作回避) |
| F-MOUSE-04 | 一度ドラッグ判定した後は、その mousedown 期間中はクリック判定にならない |
| F-MOUSE-05 | 数値(5px / 500ms)は定数として一元管理する |

#### ウィンドウ常駐・アプリ操作・終了(F-EXIT)

| ID | 要件 |
|----|------|
| F-EXIT-01 | 常にタスクバーに表示する(`skipTaskbar: false`)。タスクトレイは持たない |
| F-EXIT-02 | キャラにホバーすると操作バー(ControlBar:マイク / 音量 / 離席 / 設定 / じゃあね)を胸元に表示する |
| F-EXIT-03 | キャラ右クリックのコンテキストメニュー、または操作バーの「じゃあね」からアプリを終了できる |
| F-EXIT-04 | ウィンドウの「×」相当のボタンは持たない(フレームレス設計のため) |
| F-EXIT-05 | 終了の文言はキャラ口調で表現する(例:「じゃあね...」) |

### 2.4 会話処理(F-CONV)

| ID | 要件 |
|----|------|
| F-CONV-01 | Claude API 送信時、キャラクター人格情報を含むプロンプトを構築する |
| F-CONV-02 | プロンプトには知識ドメインに応じた振る舞い指示を含む |
| F-CONV-03 | プロンプトには関連する記憶コンテキストを含む |
| F-CONV-04 | 出力形式は JSON 固定とする |
| F-CONV-05 | 応答は chat 型のみを扱う |
| F-CONV-06 | JSON 出力の安定化は system 指示＋ロバストパーサ(F-CONV-08/09)で行う。現行 Claude 4.x は assistant Prefill 非対応のため Prefill は使わない |
| F-CONV-07 | temperature は 0.7(キャラの自然さと JSON 安定性のバランス) |
| F-CONV-08 | パース時にコードフェンス(```json ... ```)があれば除去する |
| F-CONV-09 | 応答の前後にテキスト混入があっても `{`〜`}` の範囲を抽出してパースする |
| F-CONV-10 | パース失敗・型不正時はキャラ口調のフォールバック応答を返す |
| F-CONV-11 | プロンプトに `identity.json` の `neverCallsSelf` を明示し、AI 自称しないよう指示する |
| F-CONV-12 | 応答取得後、chat メッセージ内に `neverCallsSelf` の語が含まれないか検知する |
| F-CONV-13 | AI 自称検知時は強化プロンプトで再生成を1回試みる |
| F-CONV-14 | 再生成でも検知された場合はキャラ口調のフォールバック応答を返す |
| F-CONV-15 | AI 自称検知のロジックは `identity.json` を参照する(ハードコード禁止) |

### 2.5 キャラクター人格管理(F-CHAR)

| ID | 要件 |
|----|------|
| F-CHAR-01 | キャラクター属性は外部 JSON 設定ファイルで管理する |
| F-CHAR-02 | キャラ定義は複数 JSON 構成(identity / background / knowledge_domains / fewshot ほか) |
| F-CHAR-03 | キャラクターは「歳を取らない」(時間経過で属性が変化しない) |
| F-CHAR-04 | 年齢は具体的な数字ではなく抽象表現(例:「少女」)で扱う |
| F-CHAR-05 | キャラクターは自分を「AI」「アシスタント」「モデル」等と呼ばない |
| F-CHAR-06 | 知識ドメインは5段階(high / medium / low / none / refuse)で管理する |
| F-CHAR-07 | 各ドメインに対応する Few-shot 応答例を保持する |
| F-CHAR-08 | 一人の固定キャラ(魚川トリミ)とする。キャラ依存値は JSON 外出しを維持するが、入れ替え UI・多キャラ対応は持たない |
| F-CHAR-09 | キャラは自身の人生記憶(canon)を `{id}/life-memory.json` に持てる(任意・provenance:self・読取専用)。想起プールに統合し会話に織り交ぜる |

### 2.6 知識ドメイン判定(Knowledge Router・F-ROUTE)

| ID | 要件 |
|----|------|
| F-ROUTE-01 | ユーザ入力のトピックを判定する(完全ローカル・外部往復なし) |
| F-ROUTE-02 | 判定結果を knowledge_domains と照合し、該当ドメインを特定する |
| F-ROUTE-03 | 該当ドメインの振る舞い指示と Few-shot キーを返す |
| F-ROUTE-04 | 判定不能・タイムアウト・失敗時は fallback ドメインを使用する |
| F-ROUTE-05 | Knowledge Router の失敗は本会話の進行を妨げない(ベストエフォート方式) |
| F-ROUTE-06 | 直近の判定結果を一定数キャッシュする(同一入力時の高速化) |

### 2.7 誕生日機能(任意・F-BDAY)

| ID | 要件 |
|----|------|
| F-BDAY-01 | キャラクターは任意で誕生日(月日)を持つことができる |
| F-BDAY-02 | 誕生日当日は、キャラ固有の特別反応(`celebrated`)を返せる |
| F-BDAY-03 | 当日にユーザが触れずに過ぎた場合、翌日以降に「忘れられた」反応(`forgotten`)を返せる |
| F-BDAY-04 | 反応の文言は Few-shot 例として実装する(感情パラメータの数値管理は行わない) |
| F-BDAY-05 | 「祝われた / 祝われていない」の二値の事実のみ最小状態として記録する(`active-character.json`) |
| F-BDAY-06 | 誕生日を持たないキャラクターも許容する(必須属性ではない) |
| F-BDAY-07 | キャラクター自身は加齢しない(誕生日を迎えても年齢表現は変わらない) |

### 2.8 記憶システム(F-MEM)

#### 短期記憶

| ID | 要件 |
|----|------|
| F-MEM-S-01 | 直近の会話内容(セッション内)を保持する |
| F-MEM-S-02 | 保持件数の上限を設ける(超過時は古いものから削除) |
| F-MEM-S-03 | LLM のコンテキストに直接渡される |
| F-MEM-S-04 | 各エントリは「抽出済みフラグ(`extracted`)」を持つ |
| F-MEM-S-05 | 保持件数超過時、削除前に未抽出エントリを中期記憶へ抽出する |
| F-MEM-S-06 | アプリ終了時、未抽出エントリを中期記憶へ抽出する |
| F-MEM-S-07 | 抽出処理は `extracted: false` のエントリのみを対象とする(重複防止) |

#### 中期記憶(Episodic)

| ID | 要件 |
|----|------|
| F-MEM-E-01 | 会話から抽出された出来事・事実を保存する |
| F-MEM-E-02 | 保存項目:日付・トピック・要約・タグ・重要度・カテゴリ |
| F-MEM-E-03 | JSON 形式でファイルごとに保存する |
| F-MEM-E-04 | カテゴリ別・年別の階層構造で保存される |
| F-MEM-E-05 | 全会話ログは保存しない(要約のみ) |
| F-MEM-E-06 | 各記憶に重要度(1〜5の整数)を必須で付与する |

#### 長期記憶(Semantic)

| ID | 要件 |
|----|------|
| F-MEM-L-01 | ユーザの性格・好み・価値観・人生の事実を保持する |
| F-MEM-L-02 | 変化の少ない情報のみを保存する |
| F-MEM-L-03 | 常にプロンプトの一部として読み込まれる |
| F-MEM-L-04 | 単一の JSON ファイルで管理される |

#### 記憶の保存・読込フロー

| ID | 要件 |
|----|------|
| F-MEM-F-01 | 会話終了時、LLM が会話内容から記憶抽出を行う |
| F-MEM-F-02 | 抽出結果に応じて中期・長期記憶を更新する(非破壊更新) |
| F-MEM-F-03 | 会話開始時、短期・長期記憶を読み込む |
| F-MEM-F-04 | 会話中、テーマに基づき関連する中期記憶を検索・読込する |
| F-MEM-F-05 | 検索結果の上限は5〜10件とする |

#### 検索仕様

| 検索方法 | 対応 |
|----------|---------|
| タグ / カテゴリ / 重要度 / 日付フィルタ | ✅ |
| ベクトル検索(意味検索・ローカル埋め込み ruri) | ✅ |
| 語彙＋entity 逆引き・RRF 合流 | ✅ |

#### 人生記憶・心(感情価バイアス想起)

| ID | 要件 |
|----|------|
| F-MEM-H-01 | キャラ自身の人生記憶(canon)を想起プールに統合し会話に織り交ぜる(provenance:self・読取専用) |
| F-MEM-H-02 | 各記憶に valence(感情価・中立観察)を付与する(-2〜+2・任意) |
| F-MEM-H-03 | 想起時、直近の会話から**心情を導出**し、想起にゆるやかなバイアスをかける(保存スカラーは持たない) |
| F-MEM-H-04 | 心情バイアスは想起の重みのみに作用し、応答トーン・デレを荒らさない |
| F-MEM-H-05 | 心情の数値はユーザに表示しない(導出値・好感度メーター化を避ける) |
| F-MEM-H-06 | 親しさ(接触の事実=日数・会話回数から導出・単調非減少)に応じて記憶の開示段階(disclosureLevel)を制御する。保存される好感度スカラーは持たない |

> データモデル・アルゴリズムは `03_design.md` §3.3 を参照。

### 2.9 音声入出力(双方向ローカル音声・F-VOICE)

処理はすべてローカル。脳(Claude)へ送るのは**確定テキストのみ**(音声は端末外に出さない・§3.4 / ビジョン§4.2)。

| ID | 要件 |
|----|------|
| F-VOICE-01 | TTS は `TtsEngine` インターフェースで差し替え可能(§3.6 疎結合)。実装は AivisSpeech(VOICEVOX 互換のローカル HTTP API・既定 `127.0.0.1:10101`)。音声を外部クラウドへ送らない |
| F-VOICE-02 | emotion→スタイルID/合成パラメータの対応は `{id}/voice.json` に外出しする(ハードコード禁止)。`neutral` を必須フォールバックとする。`pitchScale` は音質劣化のため使わない |
| F-VOICE-03 | 応答は読み上げ用ひらがな `reading`(任意)を持てる。TTS は `reading` 優先、無ければ表示文 `message` を読む(誤読対策) |
| F-VOICE-04 | 確定応答を文単位で合成し、文ごとに音声チャンク(WAV)を renderer へ送って逐次再生する(吹き出しは即時・音声は後追い) |
| F-VOICE-05 | STT は完全ローカル(main・`onnxruntime-node`・既定 `kotoba-whisper-v2.2`・env `ENE_STT_MODEL_DIR` で `whisper-small` 等に切替可)。録音音声は外部送信せず STT 入力にのみ使う |
| F-VOICE-06 | マイク取得は renderer の `getUserMedia`(16kHz mono)。STT モデルはコアに焼き込まず `data/models/` 配下へ別配置する(実行時に外部からモデルを取らない) |
| F-VOICE-07 | ハンズフリーは Silero VAD(v4・main・`onnxruntime-node`・同梱)で発話区間を検出し、無音継続(既定 700ms)でターン終了とみなして STT→`sendMessage` 経路へ流す |
| F-VOICE-08 | barge-in:ENE 発話中(実音声の再生中)にユーザ発話を検知したら TTS 再生を即停止する。`echoCancellation` を有効化し回り込み誤発火を抑える |
| F-VOICE-09 | マイク入力方式(push-to-talk / hands-free)を設定可能とし、`data/config/app-settings.json`(平文 JSON)に永続化する。操作バー・設定から切替できる |
| F-VOICE-10 | 同梱・配布する音声モデルは寛容ライセンス(無断クローン等を含まない)に限定する。クレジット必須の声は、クレジット文言を about/クレジット画面に常時表示する |
| F-VOICE-11 | 音声機能は best-effort:エンジン未起動・モデル未配置・合成失敗時でもテキスト会話は成立する(音声無効へフォールバックし会話をブロックしない) |

### 2.10 APIキー管理(F-KEY)

| ID | 要件 |
|----|------|
| F-KEY-01 | API キーは Electron `safeStorage`(Windows は DPAPI)で暗号化して保存する |
| F-KEY-02 | 暗号化 API キーは**アプリフォルダ内の `data/app/api-key.enc`** に保存する(Electron userData を `data/app/` へリダイレクト・ポータブル運用・§4.2) |
| F-KEY-03 | 初回起動時、または保存済みキーが見つからない場合に API キー管理ダイアログを表示する |
| F-KEY-04 | ダイアログには Anthropic Console へのリンクと取得手順を表示する |
| F-KEY-05 | 入力時に形式バリデーション(`sk-ant-` で始まる、最低50文字)を行う |
| F-KEY-06 | 保存前に Claude API への疎通テストを必ず実施する |
| F-KEY-07 | 疎通テストでエラー種別を区別する(認証失敗 / 残高不足 / ネットワーク / その他) |
| F-KEY-08 | 疎通テスト失敗時は保存せず、具体的なエラーメッセージを表示する |
| F-KEY-09 | キャラ右クリックメニュー・設定から API キー管理ダイアログを再表示できる(変更手段) |
| F-KEY-10 | API キーは Claude API 認証ヘッダ以外の用途で送出しない |

### 2.11 アプリケーション動作ログ(F-LOG)

会話内容を逐語記録する「会話ログ」機能は持たない(§1.3)。アプリの動作・障害解析のための
デバッグログのみ実装する。

| ID | 要件 |
|----|------|
| F-LOG-01 | アプリの起動・終了・エラーを `electron-log` で記録する(出力先 `data/logs/`) |
| F-LOG-02 | ログレベルは error / warn / info / debug の4段階 |
| F-LOG-03 | ログに**会話内容(ユーザ入力・AI 応答の全文)を含めない** |
| F-LOG-04 | ログに**プロンプト全文・記憶コンテキスト等の個人情報を含めない** |
| F-LOG-05 | 記録するのはメタ情報のみ(API 応答時間・Router 判定結果・エラー種別等) |
| F-LOG-06 | ログファイルはユーザが任意に削除可能 |
| F-LOG-07 | ログファイルは平文(個人情報を含まない構造) |

### 2.12 起動・終了(F-LIFE)

| ID | 要件 |
|----|------|
| F-LIFE-01 | 起動時に多重起動を防止する(2つ目のプロセスは静かに終了する) |
| F-LIFE-02 | 2つ目の起動が試みられた場合、既存ウィンドウを前面に表示する |
| F-LIFE-03 | 起動時にデータ保存可能なパスかを検証する。書込不可なら警告ダイアログを表示して終了する |
| F-LIFE-04 | クラウド同期フォルダ配下の場合は警告(続行は可能) |
| F-LIFE-05 | 開発時(`app.isPackaged === false`)はプロジェクトルートの `data/`、本番時は exe と同じディレクトリの `data/` を使用する |
| F-LIFE-06 | 起動の準備完了ゲート:口(TTS)・記憶(埋め込み)・耳(STT)・判別器が立ってから挨拶する。各段は必ず resolve する(timeout＋best-effort) |
| F-LIFE-07 | 初回起動時は ENE が自己紹介と操作方法をキャラ口調で説明する(チュートリアルダイアログは使わない)。初回完了フラグを `active-character.json` に最小状態として記録する |
| F-LIFE-08 | 2回目以降は通常の挨拶(「おかえり」等)を表示する |
| F-LIFE-09 | 終了時に短期記憶から記憶抽出を行う。異常終了からの復旧時、可能な範囲で記憶を引き継ぐ |

## 3. 非機能要件(`NFR-*`)

### 3.1 パフォーマンス

| ID | 要件 | 目標値 |
|----|------|--------|
| NFR-PERF-01 | 常駐時 CPU 使用率 | 3%以下 |
| NFR-PERF-02 | 応答表示までの体感時間(API 応答含む) | 3〜5秒以内 |
| NFR-PERF-03 | Knowledge Router の判定タイムアウト | 800ms 以内・超過時は fallback で会話継続 |
| NFR-PERF-04 | 起動から表示までの時間 | 3秒以内 |
| NFR-PERF-05 | メモリ使用量(常駐時) | 200MB以下 |
| NFR-PERF-06 | 1リクエストの入力トークン | 推奨 20K / 警告 25K(ログ) / 絶対上限 50K(拒否) |

### 3.2 軽量性(必要最小限)

無駄を持たないことを設計の規律とする。容量・常駐負荷は可能な限り小さくし、機能に不要なものは足さない。

| ID | 要件 |
|----|------|
| NFR-SIZE-01 | 配布物・常駐物は必要最小限に保つ。機能に不要な依存・資産・コードを持ち込まない |
| NFR-SIZE-02 | 重い汎用ライブラリ(画像処理・機械学習フレームワーク等)を同梱しない |
| NFR-SIZE-03 | STT モデル・音声エンジン等の大きな実行時資産はコア実行ファイルに焼き込まず、`data/` 配下へ別配置する(コアを小さく保つ) |
| NFR-SIZE-04 | 初期記憶データは小さく保つ(初回配布物に肥大した記憶を含めない) |

### 3.3 セキュリティ

| ID | 要件 |
|----|------|
| NFR-SEC-01 | API キーは Electron `safeStorage`(DPAPI)で暗号化して保存される |
| NFR-SEC-02 | 暗号化 API キーの保存先は**アプリフォルダ内の `data/app/api-key.enc`**(ポータブル運用・%APPDATA% に痕跡を残さない) |
| NFR-SEC-03 | 外部送信は Claude API への会話テキストのみに限定(送信先 URL を固定) |
| NFR-SEC-04 | テレメトリ・統計収集・クラッシュレポートを行わない |
| NFR-SEC-05 | OS 操作機能を持たない。任意コマンド実行(`exec`)・`shell:true` spawn を行わない |
| NFR-SEC-06 | 記憶・設定・ログは平文 JSON(可読性・可搬性のため。暗号化するのは API キーのみ) |

### 3.4 プライバシー

| ID | 要件 |
|----|------|
| NFR-PRIV-01 | ユーザデータはすべてローカルの `data/` に保存される |
| NFR-PRIV-02 | ユーザはデータ全体を物理削除できる。**フォルダ削除＝完全アンインストール**(%APPDATA% 等に痕跡を残さない) |
| NFR-PRIV-03 | 録音音声・会話テキストは端末外へ出さない(脳へ送るのは確定テキストのみ・音声はローカル STT 入力に限る) |
| NFR-PRIV-04 | API キーは暗号化済み。フォルダごと別 PC へコピーしても safeStorage 鍵がマシン固定のため復号できず、再入力になる(=ポータブルとして正直な挙動) |

### 3.5 可搬性

| ID | 要件 |
|----|------|
| NFR-PORT-01 | データ形式は JSON 等の標準フォーマットを使用する |
| NFR-PORT-02 | バイナリ形式・独自フォーマットは使用しない |
| NFR-PORT-03 | アプリフォルダ全体をコピーすれば別 PC で継続利用可能(API キーのみ再入力) |

### 3.6 拡張性(疎結合)

| ID | 要件 |
|----|------|
| NFR-EXT-01 | 各レイヤーは疎結合とし、型定義された契約(インターフェース・DI)経由でのみ通信する |
| NFR-EXT-02 | 任意のレイヤー内部実装を差し替えても、他レイヤーは変更不要であること(記憶検索方式・TTS/STT エンジン・視覚レンダラ等) |
| NFR-EXT-03 | 上位レイヤーは下位レイヤーの実装詳細に依存しない。依存の向きは lint で機械強制する(→ `05_architecture.md` §5) |
| NFR-EXT-04 | キャラ依存値は JSON 外出しを維持(ハードコード排除)。ただし製品は単一固定キャラで、多キャラ対応は目標にしない |

> レイヤー構成・依存の向き・1ターンの流れの**図**は `05_architecture.md`、型・関数シグネチャは
> `03_design.md` §3 を正本とする(本書は要件のみ・図は持たない)。

### 3.7 保守性

| ID | 要件 |
|----|------|
| NFR-MAINT-01 | キャラ属性・知識ルール・記憶定義はコードに埋め込まず JSON 管理 |
| NFR-MAINT-02 | TypeScript の strict mode で型安全性を確保 |
| NFR-MAINT-03 | 1ファイル300行以内を目安とする(ESLint `max-lines` で機械強制・例外は先頭で宣言) |
| NFR-MAINT-04 | レイヤー間インターフェースは型定義で契約化する |

### 3.8 信頼性

| ID | 要件 |
|----|------|
| NFR-REL-01 | Claude API 失敗時はキャラ口調のフォールバック応答を返す |
| NFR-REL-02 | Memory 読込失敗時も会話は継続できる |
| NFR-REL-03 | 不正な JSON(プロファイル・応答)を検知し、安全に処理する |
| NFR-REL-04 | 致命的エラー以外でアプリは停止しない |

## 4. データ要件

> スキーマ・ファイル命名規則・日時規約の詳細は `03_design.md` §5 を正本とする。本章はデータの
> **種別・所在・所有権**のみを定義する。

### 4.1 キャラクタープロファイル(配布物)

キャラ1体につき、人格・知識・声・見た目を定義するアセット群で構成する(`{id}/` 配下)。

| 種別 | 例 |
|------|------|
| 人格・知識定義(JSON) | identity / background / knowledge_domains / fewshot / life-memory |
| 声(JSON＋モデル) | voice.json / backchannels.json / `.aivmx` 声モデル |
| 見た目 | portrait.png(立ち絵) / animation.json / vrm.json / `.vrm` |

### 4.2 ユーザデータ(実行時生成・すべて `data/` 配下=ポータブル)

部分暗号化方式:**API キーのみ暗号化**、それ以外は平文 JSON。すべてアプリフォルダ内の
`data/` に集約し、Electron の userData も `data/app/` へ向け直す(`%APPDATA%` を使わない)。

| ディレクトリ・ファイル | 内容 | 暗号化 |
|----------------------|------|:---:|
| `data/memory/{characterId}/short-term.json` | 短期記憶(キャラ別) | — |
| `data/memory/{characterId}/semantic.json` | 長期記憶(性格・好み等) | — |
| `data/memory/{characterId}/episodic/{year}/{category}/` | 中期記憶 | — |
| `data/config/active-character.json` | キャラの最小状態(初回起動フラグ・誕生日の記録・接触の事実) | — |
| `data/config/window-position.json` | ウィンドウ位置 | — |
| `data/config/app-settings.json` | アプリ設定(マイク方式・話しかけ頻度等) | — |
| `data/app/api-key.enc` | 暗号化 API キー | ✅ DPAPI |
| `data/app/` | Electron userData(Local Storage・cache 等) | — |
| `data/logs/` | アプリ動作ログ(個人情報を含まないメタ情報) | — |
| `data/models/` | STT モデル(別配置) | — |

### 4.3 データの所有権と管理

| 要件 |
|------|
| ユーザは `data/` を自由にバックアップ・削除できる |
| アプリフォルダごと別 PC にコピーして継続利用できる(API キーのみマシン固定で再入力) |
| **完全なアンインストールはアプリフォルダの削除のみで完結する**(%APPDATA% 等に残骸を残さない) |
| 起動時、`data/app/` に API キーが無ければセットアップダイアログを表示する |

## 5. 制約条件

| 区分 | 制約 |
|------|------|
| 技術 | Electron + TypeScript(strict)で実装する。新規ライブラリ追加は最小限・追加時はユーザ承認を要する。Claude API 以外への外部通信は実装しない |
| 運用 | 書込可能なディレクトリに配置する(Program Files 不可)。クラウド同期フォルダ配下は非推奨(警告)。Windows 以外の動作は保証しない |
| ビジネス | ユーザは自身で Claude API キーを準備する。API コストはユーザ負担。収益は投げ銭制(`04_positioning.md` §7) |

## 6. 受入基準(v1.0 公開条件)

v1.0 公開時、以下がすべて成立していること(ビジョン§7「成功基準」より)。各基準は対応する
要件 ID へトレースする。

| # | 基準 | トレース先 | 判定方法 |
|---|------|-----------|---------|
| 1 | ENE がデスクトップに常駐し、ドラッグで移動できる | F-DISP-01〜05 / F-MOUSE | 目視・操作確認 |
| 2 | テキストで話しかけると、ENE のキャラとして応答が返る | F-CONV / F-CHAR | 目視 |
| 3 | PC 操作(「メモ帳を開いて」等)を頼むと、キャラ口調で「できない」と断る | F-CONV-05 / §1.3 | 動作確認 |
| 4 | 「パチンコの新台教えて」等、役の外は自然に「知らない」と返す | F-ROUTE / F-CHAR-06 | 動作確認 |
| 5 | 前回の会話を覚えていて、関連話題で思い出してくれる | F-MEM-E / F-MEM-F / F-MEM-H | 複数セッション確認 |
| 6 | API キーは暗号化保存され、外部送信は Claude API への会話のみ | F-KEY / NFR-SEC-02/03 | コード確認＋通信監視 |
| 7 | 常駐 CPU が軽く(3%以下)、配布物が必要最小限である | NFR-PERF-01 / NFR-SIZE | 計測 |
| 8 | ユーザが「AI っぽくない、ENE と話している」と感じる | F-CONV-11〜15 / ビジョン成功基準8 | **手動確認(人間判定)** |

**8番**は本プロダクトの本質であり、他を満たしても8番を満たさなければ失敗と判定する。
具体的な手動確認プロトコルは**ビジョン§7**を正本とし、`tests/acceptance/manual-check.md` で管理する。

## 7. 用語定義

| 用語 | 定義 |
|------|------|
| Character Profile | キャラの人格・背景・知識・声・見た目を定義したアセット群 |
| Knowledge Domain | キャラが知っている領域の分類(high/medium/low/none/refuse) |
| Knowledge Router | ユーザ入力からドメインを判定する層(完全ローカル) |
| Short-term / Episodic / Semantic Memory | 短期 / 中期(出来事の要約) / 長期(性格・好み)の3層記憶 |
| 人生記憶 canon | キャラ自身の来歴記憶(provenance:self・読取専用) |
| 心(感情価バイアス想起) | 直近会話から導出した心情で想起に重みをかける機構(保存スカラーは持たない) |
| Few-shot | LLM に振る舞いを学習させる応答例 |
| Fallback | 判定不能・失敗時のデフォルト動作 |
| ポータブル | アプリフォルダに全データを集約し、フォルダ削除＝完全アンインストールが成立する方式 |

*本要件定義書は、ビジョンと実装の橋渡しである。*
*「何を作るか」を ID 付きで厳密に定義し、「どう作るか」は設計書(`03_design.md`)に委ねる。*
