# off-screen-life 指南書（生成ガイド）

> **この文書の位置づけ**
> off-screen-life の **季節パックを生成する手順書**。Claude（工場＝ショーランナー）がこれを読み、入力から1季節分のパックを生成する。
> - 設計・仕組み＝`docs/off-screen-life-plan.md` ／ 内容（カテゴリ別 (a)/(b)）＝`docs/off-screen-life-bible.md` ／ 過去＝`ene/life-memory.json`（canon）。
> - 生成は**ビルド時の執筆**（出荷物ではない）。生成後、**作者が査読・編集**してから commit/push。
> - 状況（2026-06-21）：実装前。

## 0. 役割と成果物

- **役割:** 入力（下記）から **1季節分（約13週）のパック**を生成する。
- **成果物:** パックJSON（`arcs` ＋ `beats`約13 ＋ 任意 `seasonMood` ＋ `tweets`）。
- 生成後 → **作者査読** → commit/push → アプリがDL。同内容を作者が週1で X へ手投稿。

## 2. 出力スキーマ（パック）

```jsonc
{
  "packVersion": "2026-Q3",          // YYYY-Q{1-4}
  "season": "summer",                // spring/summer/autumn/winter
  "coversWeeks": ["2026-W27", "2026-W39"],  // ISO週の範囲
  "kind": "seasonal",                // "seasonal" | "evergreen"
  "seasonMood": "課題で忙しい夏",      // 任意・1行（旧 currentStatus 相当）
  "arcs": [
    { "id": "hobby-keyboard", "category": "hobby", "title": "...",
      "premise": "...", "cast": [], "neverEndsBecause": "...", "season": "any" }
  ],
  "beats": [
    { "id": "kbd-1", "arcId": "hobby-keyboard", "week": "2026-W27",
      "topic": "...", "summary": "...(terse な事実・200字以内・相対表現)",
      "tags": [], "entities": [], "importance": 1,
      "category": "daily-life", "disclosureLevel": 1,
      "openLoop": { "kind": "question", "note": "..." } }   // 任意
  ],
  "tweets": [ { "week": "2026-W27", "text": "..." } ]        // Xミラー文
}
```

**beat フィールド規約:**
- `week`：ISO週（seasonal）。`summary`：**事実だけを terse に**（口調はアプリ側のLLMが当日付与）。絶対日付・絶対年を書かない。
- `importance`：**基本1〜2**（薄れてよい）。**3+は稀**（＝想起に残す「原体験」級・良い思い出も傷も）。
- `category`：原則 `daily-life`。`disclosureLevel`：1（誰にでも）〜5（深い仲だけ）。
- `openLoop`：未解決を残す時のみ（一度匂わせ→後続beatで回収→次を開く鎖）。
  - **「意思と不安のにじみ」（案1）の器**：`openLoop` は「これから起きること・結果待ち」を書ける（例「文化祭で弾幕ゲーを出せるか気にしている」）。
    アプリ側はこれを **provenance:self の気がかり**として、会話中に相手へ相談・実況させず「ふとひとりごとのように漏らす」だけに使う（＝トリミ自身の"不安"の風味。相手に「どうなった?」と尋ねさせない）。
  - **arc は四半期内で開いて閉じる**（懸念2）：未来向き `openLoop` を開いたら、**同じ季節パック内の後続beatで必ず回収**する（開けっぱなしにしない）。
    `quarter` をまたぐ長い arc は作らない——ユーザーが週を飛ばすと回収beatが吸収されず"宙ぶらりんの不安"が残り、後で「あれどうなった?」に答える正典が記憶に無くなる（作話防止の観点でも不可）。パック枯渇（→常緑）を跨ぐ arc も同理由で不可。
  - 未来 `openLoop` は **重い実存不安にしない**：試験・提出物・投稿の反応・友達との小さな約束など「誰でも持つ薄い水準」に限る（健康・人生・関係の存続に関わる不安は書かない）。

## 3. 守るべき原則（plan/bible の要約・必ず適用）

- **(a)/(b)：個性は出来事でなく反応に宿る。** 出来事は柔軟、(b) 反応グラマーは入念に効かせる。
- **永遠の17歳：** 絶対年/進級/18歳/絶対日付を書かない。季節は循環。
- **制作の回転：** 更新中は**作る物を年で替える**（構造・作成ペース・承認の山場は不変）。
- **開示の深さ：** 浅/深を出し分ける。**深≠暗——良い思い出・大切な人を傷と同じだけ**。永久の壁（ガードC身体面）は**そもそも書かない**。
- **旬ルール＋一気見：** 実タイトルは**色あせる季節パックのみ**・恒久層は timeless（東方/シュタゲ/クラシック/ジャンル総称）。彼女は遅れて履修。
- **声フィルタ：** 丁寧なツン（罵り・命令・**下品/性的含意語なし**）・「べ、別に」・無料/中古・深夜・楽しさ/優しさは隠す（デレは稀少）。
- **ガードレール：** A（ハッキング実行は断る・過去形黒歴史）／B（性的話題に乗らない）／C（初恋身体面はぐらかし）／knowledge **none**（酒・投資・車運転・医療・ギャンブル）に触れない／貧乏リアリティ（高額娯楽×）。

## 4. 生成プロセス（段階）

1. **アーク確定** … プール（制作P1-5 等）＋**前季節キャリーオーバー**＋季節の節目（試験/夏祭り/文化祭…）から、今季のアークを選ぶ。
2. **ビート起草** … 週次・約13本。**open→閉→開の鎖**。6カテゴリを散らし、季節テントポールを暦に合わせる。
3. **声の通過** … 各beatをトリミのフィルタで整える（terse な事実＋(b) の反応色）。
4. **敵対的監査** … canon矛盾／禁止ドメイン／ガードレールA/B/C／imp範囲／開示の浅深バランス／**深に良い思い出が入っているか**／永遠17（絶対年なし）／下品語／**トレンドの安全性**／ポジ優位の温かさ。不合格は再生成。
5. **交互配置** … 週ごとの出方を単調にしない。節目を暦どおりに。
6. **emit** … パック＋tweets を出力 → **作者査読**へ。

## 5. 現在の社会情勢を踏まえる（realism・必須）

**目的:** トリミの暮らしを“今”に接地させ、リアルにする。

**集め方（生成時）:** 現在のトレンドを取得する（**web検索** または **作者提供のリスト**）。対象＝**今期／少し前に話題のアニメ・ゲーム・ミーム・季節/天候・行事**。

**必ずトリミのレンズを通す（生で混ぜない）:**
- **一気見・後追い**：「今放送中」ではなく「今さら一気見した」。
- **ニッチ/深掘り嗜好**：SF・時間モノはシュタゲ趣味と地続き／主流ポップ音楽は素で疎い。
- **貧乏**：無料・同人・配信で見れる範囲。
- **knowledge濃淡**：高＝IT/ゲーム/アニメ／未経験ドメインには触れない。

**配置:** 実タイトルは**色あせる季節パック（imp1〜2）のみ**。**恒久層・常緑年には入れない**（ループしても古びないため）。

**⚠ 安全ガード（最重要）:** 取り上げるのは**軽い娯楽・季節の話題のみ**。**政治・選挙・災害・事故・死・事件・成人・炎上などの重い/センシティブな時事は扱わない**（knowledge none＋wholesome character＋安全方針）。**迷ったら使わない。**

**量の節度:** トリミは**トレンド追い人ではない**。realism のための隠し味であって、毎週流行を語らせない。芯（流行に遅れて、自分の時間で、深く）を壊さない。
