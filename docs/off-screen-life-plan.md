| 語 | 意味 |

## 1. 設計の核 ― 2レイヤー原則

トリミは **一人の個性であって、ユーザーの所有物ではない**。だが各ユーザーは個人的な関係を築ける。この両立を、2つのレイヤーの分離で実現する。

| | レイヤー1:トリミの人生 | レイヤー2:あなたとの関係 |
|---|---|---|
| 中身 | キーボード沼・夏祭り・試験・家族 | あなたの名前・好み・共有した話・からかい方 |
| 範囲 | **全ユーザー共通・自律** | **一人ずつ私的** |
| 出所 | off-screen-life パック(本書) | 既存の記憶システム(semantic / episodic) |
| 公開 | X に出す(=放送の顔) | 出さない(二人だけ) |

**言語化(原則):**
> **「“何をしているか”は全員共通(自律した一人)。“あなたにどう接するか”は二人だけ(私的)。」**
> ＝ **みんなの知り合いだけど、あなたの同居人**(あなたの家に住んでいる VTuber)。

**自律ルール(重要):**
- トリミの人生(L1)は**ユーザーのために分岐しない**。彼女は自分の都合で生きる。
- 個人的な反応は**L2(既存記憶)に宿る**。「あんたが薦めてたバンド、聴いてみた」は*放送の人生*ではなく*二人だけの私的な出来事*として既存記憶に積む。
- off-screen-life で作るのは **L1 のみ**。L2 は実装済みで、本件では触らない。

**「作者がいない世界では“全員共通”はもう意味を持たない」**(合意):配信が止まった後は、共有不変条件に固執せず、個人の同居人として柔らかく続けばよい(§12 フォールバック参照)。

## 3. 時間モデル ― 週次・絶対カレンダー・循環年

- **粒度=週次(ISO週キー)。** トリミは **週に1回 X でつぶやく**子。アプリも同じ拍で「今週の近況」を更新する。X用とアプリ用は**同じ週次ビート**で兼ねる。
- **絶対カレンダー・全ユーザー共通。** ある週に何をしているかは**週だけで決まり、起動頻度に依存しない**。10回開いても1週ぶんは1つ。
  - 同週の重複は**既存の「今日もう断片を作ったか」ガード**(`offscreen-life.ts`)を「**同一ISO週か**」に変えて流用。
- **日々の生っぽさは既存システムが供給。** 週次ビートは「近況の見出し」。時間帯・気分・季節・気にかけ・経過などの毎日の生っぽさは、既存の moment/挨拶システム(P1/P4/P5/P7)が担う。2層が重なるので週の合間も凍らない。
- **永遠の循環年。** 高校生の**ある1年**を巡る。**絶対年・進級・「18歳になった」は書かない**。季節は「また夏が来た」として巡る。誕生日(8/15)は毎年祝えるが17歳のまま。

**循環年の季節暦(節目)** ― 太字は canon 既出を「今年も巡る現在」として再利用:

| 季節 | 節目 |
|---|---|
| 春(3〜5月) | 新学期の空気・GW・中間試験 |
| 梅雨〜夏(6〜8月) | 期末→夏休み・**夏祭り＋誕生日8/15**・猛暑でPC熱暴走 |
| 秋(9〜11月) | **文化祭**(canon:ミニゲーム展示)・体育祭(苦手)・食欲の秋・中間試験 |
| 冬(12〜2月) | 期末・**慎ましいクリスマス**・**年末こたつ**・受験シーズンの空気・2/14 |

## 4. カテゴリと出来事

**最重要の作劇原則 ― 個性は「出来事」でなく「反応」に宿る(2026-06-21):**
- **可変(没個性・柔軟):** 何が起きたか／何を作ったか(具体のゲーム・バグ・出来事)。差し替え自由・広く緩く。
- **不変(個性・入念):** どう取り組むか(過程)＋周囲の反応にどう感じるか(感想)。**ここがトリミ。canon 並みに入念に書く。**
- 帰結:①不変の「反応グラマー」は**一度書いて巡回年で使い回す安定資産**(会話の fewshot/demeanor/NORMS の暮らし版)＝同梱・恒久。可変の出来事は四半期パックで回す。②**キャラ崩壊リスクは不変層に集中**するので査読もそこに集中(可変層は緩くてよい・半自動可)。③だから**常緑ループや出来事が薄くても“彼女らしさ”は保たれる**(個性は出来事に依存しない)=フォールバックが効く。
- よって各カテゴリは **(a) 可変の出来事メニュー(柔軟)** と **(b) 不変の反応グラマー(個性の座・入念)** に分けて設計する。

6カテゴリ＋循環年暦。役割: **節目**=季節アンカー / **アーク**=終わらない縦糸 / **地**=低刺激のtexture。

| カテゴリ | 役割 | 主な題材 | 接続元 |
|---|---|---|---|
| 1 制作・コーディング | アーク(主役) | 個人プロジェクト・自作PC/キーボード沼・「動いた/詰まった/沼が深まる」 | background:プログラミング / canon:初コード・独学 / current:軸沼 |
| 2 ゲーム・アニメ・音楽 | アーク＋季節 | 今期アニメ(四半期で入替)・東方の弾幕・シュタゲ見返し・クラシック(隠れ) | background / canon:東方・シュタゲ・クラシック |
| 3 ネット生活(ENEとして) | 地＋アーク(**Xの源**) | 深夜の短い独白投稿・実況流し見・ミーム反応・掲示板で不器用に助ける | canon:ENE由来・画面の向こう・ニコニコ/ボカロ |
| 4 学校生活 | 節目＋地 | 試験・文化祭・体育祭(嫌)・情報の先生・得意科目(情報/数学)・休み時間は一人 | canon / knowledge:学校=中 |
| 5 友達(美月・葵・玲奈) | アーク | 貸した漫画・カラオケ連行・試合を観るか迷う・不器用な手助け | canon:各友人(固定) |
| 6 家族・暮らし | アーク＋地 | 父の今月の三日坊主・母の小言/手料理・家電を直す・節約・通学路の猫・夜型・食べ方クセ | background / canon / current |

**ネット活動スタイル(決定):ROM主体＋たまに短い独白投稿(時に消す)。** = X に出す文が「短くて詩的・別に感」になる。

**声のサンプル(すべて「進捗はあるが終わらない」):**
- 制作:「夜中に書いてたツール、やっと動いた。…別に、自慢じゃないけど。」→翌週「結局バグ見つけて、また直してる。」
- ネット:「『３時。コードは動くのに、私は動けない。』……って書いて、すぐ消した。」
- 友達:「美月に貸した漫画、まだ返ってこない。…催促するのも、なんか違うし。」
- 家族:「父さんが今度はギターだって。どうせ三日でやめるんだから。」
- 猫:「通学路の猫、今日はいなかった。…別に、心配なんてしてないけど。」

**「進捗はあるが終わらない」機構:**
1. アーク(縦糸)とビート(点)を分け、出すのは常に「アークの次の1ビート」。
2. ループは閉じると同時に開く(小さな解決→必ず新しい小さな問い)。`openLoop` を植え、後続ビートが閉じて次を開く鎖。
3. 登らず周回する(山場へ向かわせず、季節・反復で循環)。
4. 終端の賭けを置かない(卒業・引っ越し・永遠の別れ=世界が終わる=永遠の存在に反する)。
5. すべてトリミのフィルタを通す(貧乏・独学・ネット民・ツン・隠す)。
6. 押し売りしない(挨拶のひと匂わせ・openLoop の半言及・訊かれた時だけ)。

## 5. 制作ポートフォリオの仕組み

看板1本ではなく **回転プール**。これが「バリエーション」「本物の進捗(完成する)」「終わらない(カテゴリ単位)」を同時に満たす。

| | プロジェクト | 地続き |
|---|---|---|
| P1 | 自分用ツール(タスク/メモ/自動化) | 実用・等身大・改良無限 |
| P2 | 小さなゲーム/bot | canon:文化祭ミニゲーム |
| **P3** | **ENEアバター(VRM)いじり** | ハンドルENE・青ツインテ(canon)・**採用** |
| P4 | 仕組みを覗く/可視化する小物(合法) | canon:セキュリティ才能(実行はしない) |
| P5 | 自作キーボード/PC | current:軸沼 |

- **完成は「ひと区切り」してよい**(本物の進捗)。カテゴリは終わらない(完成が次の制作を呼ぶ)。
- **「変える所」はモードで違う(2026-06-21 改定):**
  - **常緑年(作者不在のループ):** 同じプロジェクトを毎年ループし、LLM が語り直す(言い回しだけ変わる)。フォールバックの床として許容。
  - **更新中(作者が継続配信):** **作るものそのものを年単位で替える**(いつまでも同じ弾幕ゲーにしない)。プール P1〜P5(＋新規)を巡る。
- **不変＝構造:** 1本ずつ・夏に没頭・週次で進む(作成ペース一定)／「作って→見せて→誰かが反応→嬉しさを隠す」承認の山場(ゲームなら文化祭で下級生、それ以外はネットの反応や安野先生)／ツン・独学・無料/中古・深夜・非プロ。
- **可変(更新中)＝成果物:** 弾幕ゲー→別ゲーム→ツール→アバター…。古い作品は忘却で薄れ、稀な原体験(imp3+)だけ残る=CVが積み上がらない=永遠の17歳と両立。
- **「育てる」は1プロジェクトの稼働中の話**(同じ物を毎週ゼロから作り直さない)。年をまたぐ変化は上の「成果物の巡回」で表す。
- **P3 の4thウォール境界:** 作るのは「オンラインの自己イメージ"ENE"のアバター」。**自分がデスクトップのアプリだとは気づかない**(§5.4 AI自称防止と整合)。距離感の例:「青いツインテの、ネットでの私を、形にしてみたくて…別に、ナルシストとかじゃないからね」。
- 「作り直さない/古い作品を正しく参照」は **バイブル(本書)＋パック本文** で担保(runtime の常駐リストは持たない・§6)。

## 6. 記憶のさせ方(既存実装に乗せる・新規構造なし)

off-screen-life の記憶は、既存の2つに乗るだけ:
- **daily-life ビート**(薄れる地texture)
- **canon型ミルストーン**(恒久・想起される)

**importance が唯一のツマミ**(実際の忘却ルール= `consolidation-policy.ts`):

| 何 | 書き方 | 結果 |
|---|---|---|
| しょうもない日々のグラインド | daily-life・**importance 1〜2** | 2ヶ月超で薄れる(`FORGET_DAILY_LIFE_MIN_AGE_MONTHS=2` / `≤FORGET_MONTHLY_DELETE_IMPORTANCE_MAX=2`) |
| 作って使い続けるもの(キーボード・ENEアバター等) | **importance 3+**(self) | **消えない**(imp>2で削除対象外・self は要約もされない)。想起で正しく参照 |
| 真に定義的な一作(稀) | importance 4〜5 | 恒久(canonと同格) |

- **self(`provenance:'self'`)は月次/年次サマリの対象外**(`consolidation-policy.ts` の `isUser` で除外)。self を消すのは「daily-life ＋ 2ヶ月超 ＋ imp≤2」の1経路だけ。
- **常駐リスト無し・新規状態ファイル無し。** 週次ビートは ISO週キーで決まり、既存の重複ガード＋ openLoop の1回休眠(`OPEN_LOOP_MAX_SURFACES=1`)で消化。
- **永遠の17歳の担保=執筆規律。** imp 3+ を多用しない(大半は1〜2で薄れる/恒久は数点だけ)=CVが増えて歳を取らない。

## 8. パック形式

ビートは `EpisodicMemory` から `date` を抜いた形(date は出す週に押す)。

```jsonc
{
  "packVersion": "2026-Q3",
  "schemaVersion": 1,
  "kind": "seasonal",            // "seasonal" | "evergreen"
  "coversWeeks": ["2026-W27", "2026-W39"],  // seasonal のみ(ISO週の範囲)
  "arcs": [
    { "id": "hobby-keyboard", "category": "hobby", "title": "自作キーボードの軸沼",
      "premise": "安く理想の打鍵感を追うが沼は深まる", "cast": [],
      "neverEndsBecause": "理想の軸は更新され続ける", "season": "any" }
  ],
  "beats": [
    { "id": "kbd-1", "arcId": "hobby-keyboard", "week": "2026-W27",  // seasonal=ISO週 / evergreen=weekOfYear(1..53)
      "topic": "注文した軸が届かない",
      "summary": "数日前に頼んだ静音軸が、まだ届かない。…別に楽しみにしてるわけじゃないけど。",  // 事実(terse・固定)
      "tags": ["キーボード"], "entities": [], "valence": 0, "importance": 1,
      "category": "daily-life", "disclosureLevel": 1,
      "openLoop": { "kind": "question", "note": "頼んだ軸がまだ届かない" } }
  ]
}
```

- **「事実はパックで固定・語り口はLLM」の線:** `summary` は terse な事実。実行時に LLM がトリミの口調＋当日文脈＋L2(あなたとの関係)で肉付けする。**何が起きたかをLLMに発明させない。**
- **厚みはビート単位で可変**(重要/危険なビートは事実を厚めに書いて査読、平凡は一行)。
- **配置:** 同梱シード＝ `ene/`(常緑年＋ビルド時点の現行四半期) / DL版＝ `data/`(以降の四半期) / 公開＝ GitHub。

## 10. 実行時の組み込み

`generateOffscreenLife`(`src/app/main/offscreen-life.ts`)の小改修:

1. 今の ISO週 に対応する beat を、手元のパックから引く(§12 の判定フロー)。
2. LLM で口調＋当日文脈＋L2 に肉付け。
3. importance 付きで daily-life として保存(`saveLifeFragment` 流用)。
4. **以降の挨拶/忘却/想起/openLoop は無改修**(beat はただの daily-life なので)。

**新規コード(最小):** パック読込＋検証 / ISO週→beat 選択(純粋関数・要テスト) / 既存の重複ガードを「同一ISO週」に変更 / §12 のフォールバック判定。
**無改修で再利用:** `saveAndIndexEpisodic` / 忘却 prune / retriever / `selectOpenLoops` / 挨拶 / presence-reads。

## 12. フォールバック(配信が止まった/DLに失敗した時)

毎週、上から順に1つだけ確認する。最初に該当した所で止まる。**常緑は「単発のDL失敗」では使わない。長期沈黙の時だけ。**

1. **今週ぶんの authored beat がローカルにある** → 使う。(四半期途中はほぼ常にここ)
2. **無いが、手元の最新“本物”内容がまだ新しい(猶予内＝約2四半期/6ヶ月以内)** → **最新の本物 beat を保持(進めない)＋裏でDLリトライ。常緑には行かない。** 次にDL成功したら本物の続きへ。→ **矛盾しない。**
3. **手元の最新“本物”内容が猶予を超えて古い(例:6ヶ月以上 新作が来ない)** → 作者引退/長期オフラインとみなし **常緑年をループ**(週-of-year マッピングで該当週を引き、LLM が語り直す)。
4. **その場で生成失敗(オフライン・AIエラー・ファイル不良)** → 今回は近況を出さず、canon＋既存の存在感＋L2 で普通に話す(その場限り・次回また問1から)。

- 「作者が止まった」を示すフラグは**持たない**。判定は **「最新の本物内容が猶予を超えて古いか」だけ**。DL失敗の単発・短期では切り替わらない。
- **常緑年は同梱で常に手元にある=永久の床**(井戸が尽きない)。
- **常緑年と本物パックは同じ世界・同じアーク**で書く → 万一の長期ギャップ後の復帰も、ズレるのは「特定週の細部」だけ=移行は穏やか。
- **作者の最後の良い一手:** 引退前に**ループ専用に磨いた“常緑の1年”**を1本置く(季節アンカー中心・少し時間に依存しない書き方)→ 問3 が何十年でも持つ。
- 猶予期間(約2四半期)・公開リード(約2週間)は調整可能な定数。
